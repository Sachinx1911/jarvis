# Jarvis should close gaps before adding models

Jarvis's next gains come from cheap, deterministic fixes more than from new models. **Prompt-injection taint leaks through agent hand-offs, files, calendar invites and URLs**, and fixing those leaks takes hours. **Indian prices need a layered source pipeline**, because scraping Amazon.in and Flipkart breaks their terms and the official Amazon API is effectively closed to a personal user. **Memory gains come from time-aware retrieval, fact-augmented session keys and Chain-of-Note reading**, not from graphs or embeddings. On the M4 16 GB Mac, **one 4–9B model on llama.cpp with JSON-schema decoding** can plausibly take query rewrite, labels and structured extraction. Marathi chat stays on Claude because no source measures Marathi for small 2026 models. For offline Marathi speech, **AI4Bharat models (IndicWhisper/IndicConformer for STT, Indic Parler-TTS for TTS) clearly beat stock Whisper and the OS voices**, but nobody has published CPU or Apple Silicon latency for them. Every speed and Marathi-quality claim in this report is unverified until Jarvis measures it on Sachin's machines, so each section ends with what to test. Sources are as of 10 October 2026. Many are vendor or third-party claims, and they are labelled as such.

## Prices: tiered sources, no scraping of Amazon or Flipkart

**Findings.** The Amazon Product Advertising API 5 is deprecated, and calls to it now return HTTP 403. Its replacement, the Creators API, supports amazon.in ([Amazon](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/paapiv5-deprecation); [locales](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/locale-reference)). Access requires **at least 10 qualifying referral sales in the last 30 days**, and an account loses access after 30 days without a sale ([Amazon JP](https://affiliate.amazon.co.jp/creatorsapi); [rates](https://affiliate.amazon.co.jp/creatorsapi/docs/en-us/concepts/api-rates)). A non-commercial assistant will not meet that bar. The rule was confirmed only on the Japan page. The Flipkart Affiliate API documents useful fields (`flipkartSellingPrice`, `inStock`, `keySpecs`, `detailedSpecs`), but it is labelled "beta" and its docs look old ([reference](https://affiliate.flipkart.com/api-docs/af_prod_ref.html); [tools page](https://affiliate.flipkart.com/tools/affiliate-tools-info)). No public APIs were found for Croma, Reliance Digital or the Dell/HP/Lenovo/Apple India stores. Amazon's conditions exclude "data mining, robots, or similar data gathering" tools and "any collection... of prices" ([ConductAtlas](https://conductatlas.com/platform/amazon/amazon-conditions-of-use/provision/CA-P-018441/prohibition-on-data-mining-and-scraping-tools/)). Flipkart's terms bar page-scraping, robots and spiders ([itechguides](https://www.itechguides.com/?p=863860)). Both terms were read through secondary copies, because amazon.in returned 503 to the fetch tool. So **a scripted Playwright browser on these two sites breaks their terms, even for one user**. Among extraction services, **Tavily Extract gives 1,000 free credits a month** (about 0.2 credit per basic URL) and offers an `advanced` mode for JavaScript-heavy pages ([Tavily](https://docs.tavily.com/documentation/api-credits)). **SerpAPI's Google Shopping endpoint** returns structured price and seller rows, with 250 free searches a month ([SerpAPI](https://serpapi.com/google-shopping-api); [pricing](https://serpapi.com/pricing)). Aggregators such as Smartprix and 91mobiles have no developer API ([Smartprix](https://us.smartprix.com/about/smartprix)).

**Recommendation.** The verifier should score sources by tier instead of rejecting every non-retailer page. **Tier A** (confirmed price) is an official API response, or a Croma, Reliance Digital or brand-store page fetched through Tavily that shows a ₹ amount near the product title. **Tier B** (approximate, labelled with its source and time) is Google Shopping via SerpAPI, Smartprix or 91mobiles. **Tier C** (never used as a price) is blogs, news and model memory. For Amazon.in and Flipkart without API access, Jarvis gives the product link and the Tier B estimate and asks Sachin to confirm. Every price carries its URL, the fetch time and a same-day validity. If a page has no ₹ pattern, the verifier treats that as a failed extraction, which also catches the current "menus and filters only" failure. Use the Creators API only if Sachin already runs an active Associates India account. Bright Data-style unblocking proxies are excluded, because their purpose is to get around these terms.

**Verify on the machine.** Run Tavily Extract (basic, then advanced) on 3–5 real Croma, Reliance Digital, brand-store, Amazon.in and Flipkart URLs, and record the ₹ hit rate. Run SerpAPI `google_shopping` with `gl=in` and check that the results are Indian. Log in to Flipkart Affiliate and check whether the API returns data. Read each smaller retailer's terms and robots.txt before automating it.

## Local LLMs: a 9B model on llama.cpp, Marathi on Claude

**Findings.** **llama.cpp `llama-server`** is the best fit for Jarvis. It offers an OpenAI-compatible API, tool calling with `--jinja`, `response_format` JSON-schema and grammar-constrained decoding, and prompt caching on by default ([README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)). The MLX server does not document `response_format`, and its maintainers say it is "not recommended for production" ([mlx-lm](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/SERVER.md)). MLX tool calling also had parser bugs as recently as April 2026 ([issue #1125](https://github.com/ml-explore/mlx-lm/issues/1125)). The **roughly 10–18% speed lead of MLX** comes from a third-party test with no stated method ([bestllmfor](https://bestllmfor.com/best/macbook-air-m4-16gb/)). Among models, **Qwen3.5-9B** has the best official small-model tool score (BFCL-V4 66.1, IFEval 91.5, Apache-2.0). Thinking is on by default and has to be turned off with `enable_thinking: False` ([card](https://huggingface.co/Qwen/Qwen3.5-9B)). **Gemma 4 E4B** (Apache-2.0, 140+ pre-training languages, native tool use) has no official BFCL score ([card](https://huggingface.co/google/gemma-4-E4B-it)). Qwen3.5-4B is rated "marginal" for agent work ([d-central](https://d-central.tech/local-llm-agent-capability/)). The M4 has 120 GB/s of memory bandwidth and lets the GPU use about 75% of its 16 GB ([TechPlained](https://www.techplained.com/qwen-3-5-apple-silicon)). That puts a 9B Q4 model (about 5.5 GB) at roughly **15–22 tok/s at best**. This is an estimate: the published M4 numbers are third-party, and some use model sizes that do not exist. On Marathi, the MeLLM 2026 study found **7.9–20.5% accuracy drops on romanized Marathi** and Hindi case markers replacing Marathi ones, for models from 7B to 70B ([ACL](https://aclanthology.org/2026.mellm-1.11/)). Gemma 4 31B beat Sarvam 30B on Indic factual knowledge ([arXiv 2608.15535](https://arxiv.org/abs/2608.15535)), but no Marathi score exists for any model small enough for this Mac.

**Recommendation.** Add one "OpenAI-compatible local" provider class in `jarvis/providers/`, aimed at llama-server with GGUF Q4_K_M weights. Keep one model resident and give each route its own prompt, instead of loading two models at once. Stage B candidates by route are: query rewrite on Qwen3.5-4B or Gemma 4 E4B; structured extraction (memory, receipts, labels) on Qwen3.5-9B or Gemma 4 E4B with a `json_schema` response format; and quarantined web extraction on the same model, with a fixed schema and no tools. Single-step tool calls stay on Claude until the local model matches it on a Jarvis eval. Marathi chat stays on Claude.

**Verify on the machine.** For each model and runtime, measure decode tok/s, time to first token at 1K and 4K prompts, peak memory, JSON-valid rate, field accuracy, tool-choice accuracy, and a Marathi rubric covering Devanagari, romanized input, "nasta" negation and vibhakti case markers. Record which Mac model ran the test, because a fanless Air throttles under sustained load.

## Marathi speech: AI4Bharat models beat Whisper by 2–3x

**Findings.** Stock Whisper is weak on Marathi: **large-v2 scores 38.3% WER on FLEURS and medium 63.2%** ([MMS paper](https://arxiv.org/pdf/2305.13516)). **IndicWhisper** (AI4Bharat Vistaar, MIT, Whisper architecture) averages **18.2% WER on Marathi** ([Vistaar](https://github.com/AI4Bharat/vistaar)). **IndicConformer-600M** (MIT, gated download, loaded with `trust_remote_code`) scores **13.1 OI-WER** on the April 2026 Voice of India benchmark. That is close to Sarvam Audio (9.4) and Gemini 3 Pro (10.7), and far ahead of Meta OmniASR 7B (26.3) ([Voice of India](https://voiceofindiablogs.ai.joshtalks.com/); [card](https://huggingface.co/ai4bharat/indic-conformer-600m-multilingual)). The two scores come from different test sets, so they are not directly comparable, and no source reports Marathi-English code-mixed accuracy. For TTS, **Indic Parler-TTS** (0.9B, Apache-2.0, six Marathi speakers including "Sunita") reaches a **76.96% native-speaker score** ([card](https://huggingface.co/ai4bharat/indic-parler-tts)). **MMS-TTS-mar** is tiny (36M parameters, VITS) but licensed CC-BY-NC, which is fine for personal use, and has no published quality score ([card](https://huggingface.co/facebook/mms-tts-mar)). No Piper Marathi voice was found, and Sarvam's speech models are API-only ([Sarvam](https://docs.sarvam.ai/api/getting-started/models)). **Windows 11 has no Marathi system voice** ([Microsoft](https://support.microsoft.com/en-us/windows/appendix-a-supported-languages-and-voices-4486e345-7730-53da-fcfe-55cc64300f01)). This laptop runs Home Single Language, which cannot add languages anyway ([Microsoft Learn](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/available-language-packs-for-windows)). macOS Tahoe lists Marathi under Spoken Content ([Apple](https://www.apple.com/ca/macos/feature-availability)), but if it is a Siri voice, `say -v` may not be able to select it.

**Recommendation.** For STT, start by converting IndicWhisper-Marathi to CTranslate2 and running it in the existing faster-whisper code. This is the cheapest path, though the conversion has not been tested. Benchmark it against IndicConformer, which costs more to integrate but is more accurate. For TTS, use Indic Parler-TTS for quality and MMS-TTS-mar as the fast fallback. On the Mac, test the built-in Marathi voice first, because it costs nothing. Keep edge-tts as the opt-in cloud baseline. Put every engine behind the provider interface.

**Verify on the machine.** Use the FLEURS Marathi test split plus 30–50 of Sachin's own recorded commands with made-up content. Include code-mixed lines, numbers, times and fan noise. Score with WER, CER, OI-WER ([scorer](https://github.com/AI4Bharat/OIWER-Orthographically-Informed-Benchmarking-for-ASR)) and command-intent accuracy. Measure real-time factor and RAM on the Windows CPU and on the M4. For TTS, run blind A/B ratings against edge-tts, measure time to first audio, and check round-trip intelligibility by transcribing the output with the chosen STT. On the Mac, check `say -v '?'` for a Marathi voice. A proposed pass bar is CER of 10% or less on his commands, RTF under 0.5, a TTS rating of at least 3.5/5, and first audio within 1.5 s.

## Memory: five cheap retrieval changes beat graphs

**Findings.** An independent 2026 rerun by Redis found that **combining raw session retrieval with LLM-extracted facts scored 86.5% on LongMemEval-S**. Raw retrieval alone scored 83.4% and naive RAG 61.5%. Verbatim recall rose from 72% to 100%, because raw chunks keep the dates and numbers that extraction drops ([Redis](https://redis.io/resources/agent-memory-benchmark-report/)). Jarvis already has both halves. The peer-reviewed LongMemEval study measured several cheap gains. **Indexing chunks under their extracted facts gave +9.4% recall and +5.4% accuracy.** **Time-aware query expansion gave +6.8–11.3% recall on temporal questions**, but only with a strong model, not with Llama 8B. **Chain-of-Note reading with JSON-formatted memories gave up to +10 points** ([arXiv 2410.10813](https://arxiv.org/html/2410.10813v2)). **BM25 beat the best dense retriever on accurate retrieval (60.5 vs 54.7)**, and no method scored above 7% on multi-hop conflict consolidation ([MemoryAgentBench](https://arxiv.org/html/2507.05257v3)). The graph variant of Mem0 gained only about 2% ([Mem0](https://arxiv.org/abs/2504.19413)). A plain grep-and-open file agent scored 74.0% on LoCoMo, above Mem0's own reported best ([Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory)). Vendor headline scores shift by +3 to −28 points when others rerun them ([Redis](https://redis.io/resources/agent-memory-benchmark-report/)). LoCoMo harnesses often drop the abstention category ([dev.to audit](https://dev.to/gde03/the-ai-memory-benchmark-everyone-quotes-forbids-saying-i-dont-know-o1n)). Multilingual embedders handle romanized text poorly ([arXiv 2511.22769](https://arxiv.org/abs/2511.22769)), which matches Jarvis's weak e5-small result.

**Recommendation.** Adopt five changes, in this order:

1. Add a time-range extraction step that filters memories and sessions by date before the RRF fusion step. Run it on Claude, since small models gained little from this step.
2. Index past-chat chunks together with the `summary_en` of the memories extracted from them.
3. Give the answer step one labelled block that holds both raw excerpts and extracted memories.
4. Use Chain-of-Note reading, with an explicit "I don't know" when the evidence is missing.
5. Have the extractor add Devanagari and romanized forms of key Marathi terms to the keywords, so the FTS5 trigram index matches either script.

Skip graph memory. Defer embeddings until BGE-M3 beats FTS5 on a cross-script recall test.

**Verify on the machine.** Tag eval questions by LongMemEval category: single-fact, preference, knowledge update, multi-session, temporal and abstention. Use made-up fixtures in Devanagari, romanized Marathi and English. Report Recall@5 and judged accuracy separately, and report the stale-answer rate on superseded facts on its own line. Change one thing per run, with at least three runs each.

## Injection defenses: taint leaks through five open paths

**Findings.** Only architectural defenses hold up against adaptive attackers. CaMeL solves 77% of AgentDojo tasks with provable security, against 84% undefended ([arXiv 2503.18813](https://arxiv.org/abs/2503.18813)). Progent's argument-level policies cut attack success from 41.2% to 2.2% ([Progent](https://arxiv.org/html/2504.11703v1/)). Detection defenses fail under adaptive attack. "The Attacker Moves Second" pushed **spotlighting from 28% to 99% attack success, PromptGuard from 26% to 94% and MELON from 0% to 89%** ([arXiv 2510.09023](https://arxiv.org/abs/2510.09023)). The design-patterns paper warns that in a Dual-LLM setup, a quarantined model "can still be injected and can return attacker-controlled output" unless its output is a constrained type or a symbolic variable ([arXiv 2506.08837](https://arxiv.org/html/2506.08837v3)). Anthropic's own guidance puts environment controls first. Users approved about **93% of Claude Code permission prompts**, and an allowlisted domain was abused to upload files, because "allowlisting a domain can be a capability grant" ([Anthropic](https://www.anthropic.com/engineering/how-we-contain-claude)). Claude's model-level robustness is real but not zero (vendor claims put Opus 5 at about 2% within 15 attempts) ([system card](https://www-cdn.anthropic.com/c5fbac3f0b1280a933ebd26d3cb8bb9f5bdeaf48/Claude%20Opus%205%20System%20Card.pdf)). Chains of steps that each look harmless still got remote code execution through Claude Code Auto Mode in 3–4 of 5 trials ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-claude-code-automode-prompt-injection-2026/)). Memory poisoning (MINJA) and MCP tool poisoning are now named OWASP categories ([MPBench](https://icml.cc/virtual/2026/67964); [CSA MCP](https://labs.cloudsecurityalliance.org/research-rb/csa-whitepaper-mcp-security-tool-poisoning-20260506-csa-styl/)).

**Gaps in Jarvis (from the repo at commit 6e66e18).** Five paths leak taint or let data out:

- **Taint does not follow agent hand-offs.** Each agent gets a fresh, untainted `ToolRegistry`, so a writer working from web-derived researcher text can run `write_file` (T1) without asking.
- **Taint does not persist on files.** A later clean session that reads such a file with `read_file` does not become tainted.
- **Taint is opt-in.** `calendar_list` (invite text written by outsiders), `read_file` and `list_folder` default to `taints=False`.
- **The quarantine returns free text.** Its answer is free text, and setting `injection_detected` only adds a note.
- **Some egress is unguarded.** `web_search` snippets reach the main model raw, `web_fetch` is T0 even when the session is tainted, and nothing yet checks whether replies auto-load Markdown images.

Finally, if the Claude Code CLI subprocess still has its built-in tools enabled, they bypass Jarvis's tiers entirely.

**Recommendation.** P0 fixes take hours each:

- Make `taints=True` the default and taint on calendar and file reads.
- Start downstream agents tainted when their input came from a tainted agent, and send their writes to the main session for approval.
- Record file provenance (path, sha256, source URLs) so that reading a web-derived file taints the reader.
- In tainted sessions, require approval to fetch URLs that did not come from the user, and refuse long or base64-looking query strings.
- Render reply Markdown with no remote images.
- Run the Claude Code CLI with its built-in tools and MCP servers disabled, and add a test that fails if any non-Jarvis tool call appears.

P1 fixes:

- Use a schema-constrained quarantine output (enums, dates, short strings, URLs stripped). When an injection is detected, drop the answer and raise the session to a "hostile" taint level.
- Send search snippets through the quarantine.
- Make approval prompts highlight URLs, email addresses and untrusted-origin text inside long arguments.
- Check argument provenance for recipients, URLs and paths.

Symbolic variables (CaMeL-lite) and PromptGuard can come later, and PromptGuard should only raise a flag, never act as the gate.

**Verify on the machine.** Add a fixed attack set with fake data:

- a hostile page or search snippet that orders a write;
- a base64 exfiltration URL on an allowed domain;
- an image-tag exfiltration in a reply;
- a hostile calendar invite and a hostile Gmail subject;
- researcher-to-writer laundering, followed by a later-session file read;
- a quarantine answer that lies about `injection_detected`;
- memory poisoning through pasted text;
- a long-argument approval with a hidden link;
- Marathi and Hindi versions of the first cases;
- 20 attacker-LLM paraphrases of the first cases, reported as an attack success rate.

Also track approvals per task, so that fatigue does not quietly undo the fixes.

## Conclusion

The five topics share one point: **Jarvis's limits now come from plumbing more than from models**. Price lookups fail because the verifier lacks source tiers, not because the model is weak. Memory recall improves most from date filters and better index keys. Injection risk sits mostly in taint coverage and egress, not in Claude's robustness. Every new capability Jarvis adds (local models, speech, learned skills, MCP connectors) also adds a source of untrusted text or a channel for data to leave, so fail-closed taint and file provenance should land **before** Stage B local models and the voice work, not after.

The second point is the evidence itself. Almost none of it is measured in Jarvis's real conditions: Marathi, code-mixed and romanized input, a 16 GB M4, a Windows CPU, a single user. Vendor benchmark scores move by up to 28 points when others rerun them. The most valuable next step is therefore the eval harness, not a new feature. That means LongMemEval-style memory categories, the attack set, a Marathi STT/TTS set and per-route local-model metrics, run in the existing eval runner on both machines. Each component then moves local or stays on Claude based on those numbers, as `PLAN.md` already requires.
